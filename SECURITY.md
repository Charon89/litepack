# Security policy

## Supported versions

LitePack has no release yet. Until it does, report against the `main` branch. After the first release, the latest
release is the supported version.

## How to report a vulnerability

Report it privately, through GitHub's private vulnerability reporting: open the repository's **Security** tab and
press **Report a vulnerability**, or go straight to
<https://github.com/Charon89/litepack/security/advisories/new>.

Never report a vulnerability in a public issue, pull request or discussion. Nothing else is published as a way to
report one: no email address.

## What to include

- The version, or the commit, you tested.
- The steps that show the problem.
- An archive that reproduces it, if one is needed. Say what it is and where it came from.
- The impact, as you see it: what an attacker gains, and what they must already have.

## What happens next

Every report is read and acted on as soon as possible. LitePack is maintained by one person, so no deadline is
promised, for an answer or for a fix.

## Disclosure

Disclosure is coordinated: please keep the report private until a fix is available, or until we have agreed on a
date together. The advisory credits you by name if you want that; say so in your report.

## The security model

What the sandboxed worker can and cannot reach, and the risks that remain, are described on the site:
<https://charon89.github.io/litepack/security.html>.
